NIST CSF 2.0: Gap Analysis Project

A practical cybersecurity assessment and infrastructure remediation plan for Fintech Innova Inc.

Phase 1: Executive Summary & Scope

This project evaluates the current cybersecurity posture of Fintech Innova Inc. (a fictitious financial technology startup) against the NIST Cybersecurity Framework (CSF) 2.0. The goal is to identify vulnerabilities in their cloud and on-premise infrastructure and provide a strategic roadmap for mitigation.

  • Framework: NIST CSF 2.0 Core (Govern, Identify, Protect, Detect, Respond, Recover).
  • Scope: Corporate internal network (LAN), core routing infrastructure, and cloud-hosted databases.
  • Objective: Align technical controls with PCI-DSS requirements to ensure data privacy and network integrity.

Phase 2: Findings & Gap Matrix

During the assessment, several critical gaps were identified comparing the organization's Current Profile against the Target Profile. The findings emphasize network security and access control deficiencies.

NIST Code Identified Gap (Current State) Remediation Action Risk Level
PR.AC-05 (Network Segregation) Flat network topology. Guest Wi-Fi and production servers share the same logical subnet. Implement VLANs and configure strict Access Control Lists (ACLs) on core switches. CRITICAL
PR.AA-01 (Authentication) Cloud database administrators use single-factor authentication (passwords only). Enforce mandatory Multi-Factor Authentication (MFA) across all elevated accounts. CRITICAL
ID.AM-01 (Asset Inventory) Hardware inventory is maintained via outdated manual spreadsheets. Deploy automated network scanning (e.g., Nmap) to build a dynamic asset map. HIGH
RS.MA-01 (Incident Response) No formalized incident response document or communication plan exists. Draft an Incident Response Playbook defining roles during a cyberattack. MEDIUM
GV.PO-01 (Security Policies) No formal Access Control Policy; sysadmins create accounts based on verbal requests. Draft and enforce a strict Role-Based Access Control (RBAC) policy. CRITICAL
GV.OC-04 (Critical Dependencies) Core network relies on a single ISP. An outage halts all financial transactions. Implement a secondary ISP connection with automated WAN failover. CRITICAL
ID.AM-02 (Software Inventory) Unauthorized software (Shadow IT) found on several Linux and Windows endpoints. Deploy application whitelisting and centralize software deployment. HIGH
ID.RA-01 (Vulnerability Scans) Core routers and firewalls are never scanned for CVEs or outdated firmware. Schedule automated weekly vulnerability scans using OpenVAS/Nessus. CRITICAL
PR.DS-02 (Data in Transit) Network engineers manage core switches using unencrypted Telnet and HTTP. Disable Telnet/HTTP globally; enforce SSHv2 and HTTPS for device management. CRITICAL
PR.AC-06 (Physical Access) The on-premise server rack is located in an unlocked utility room. Install biometric locks and CCTV monitoring for the server room. HIGH
PR.AT-01 (Awareness Training) Staff frequently click on suspicious links; no phishing training exists. Launch a quarterly Phishing Simulation and Cybersecurity Awareness program. HIGH

Phase 3: Comprehensive Remediation Strategy

To systematically address the 10 identified gaps, the remediation roadmap has been divided into three operational pillars: Infrastructure, Operations, and Governance. This ensures a balanced allocation of IT resources.

Pillar 1: Network & Infrastructure Hardening

  • Secure Device Management (PR.DS-02): Access all Cisco/infrastructure devices and disable Telnet (no ip server telnet). Generate RSA keys and enforce SSH version 2.
  • High Availability (GV.OC-04): Configure a dual-WAN router setup. Implement routing protocols (e.g., OSPF or BGP) or IP SLA to automatically failover to a backup ISP if the primary link drops.
  • Log Centralization (DE.CM-01): Deploy a central Syslog server (e.g., using Linux-based Rsyslog or an ELK stack). Configure all switches, routers, and firewalls to forward logs to this secure, centralized vault.
  • Physical Security (PR.AC-06): Restrict server room access with badge readers and log all physical entry events.

Pillar 2: Proactive Operations & Testing

  • Vulnerability Management (ID.RA-01): Integrate tools like Nessus or OpenVAS to scan the 10.0.0.0/16 network weekly. Prioritize patching devices with critical CVEs (Common Vulnerabilities and Exposures).
  • Restoration Drills (RC.RP-02): Establish a "Restoration Friday" protocol on the first week of every month to restore the primary SQL database into an isolated VirtualBox/VMware sandbox to verify data integrity.
  • Endpoint Control (ID.AM-02): Implement Group Policy Objects (GPO) for Windows and execution policies for Linux to block unauthorized software installations.

Pillar 3: Governance & Human Risk

  • Access Policy (GV.PO-01): Draft a strict Role-Based Access Control (RBAC) document. Require IT tickets and manager approval for any new account creation or privilege escalation.
  • Phishing Simulations (PR.AT-01): Deploy a managed awareness platform to send monthly simulated phishing emails. Users who fail must complete a 10-minute mandatory security module.
  • Tabletop Exercises (RS.MA-02): Run a 2-hour simulated cyberattack drill with the IT team and management every 6 months to ensure everyone knows their role during an actual crisis.

Phase 4: Conclusion & Business Impact

By executing this remediation roadmap, Fintech Innova Inc. transforms its security posture from a reactive state to a proactive, governance-driven model. The implementation of VLAN segmentation and MFA directly reduces the attack surface, ensuring compliance with financial regulations and safeguarding customer data.
